# 환승을 포함한 여러 편명의 공항 날씨와 옷차림

`PRODUCT.md` 성공 기준 2단계의 작업 단위입니다. 1단계([flight-weather-outfit](../flight-weather-outfit/spec.md))의 화면과 동작을 그대로 이어 가고, 편명을 여러 개 받아 출발, 환승, 도착 공항을 한 화면에 보여 줍니다.

## 사용자 결과

승객이 첫 비행기의 출발 날짜와 비행 순서대로 모든 편명을 입력하면, 출발 공항, 환승 공항(들), 도착 공항 각각의 예정 시각 날씨예보와 그에 맞는 추천 옷이 한 화면에 표시됩니다. 환승 공항의 날씨는 실제 환승편 탑승 시각 기준입니다.

## 1단계에서 유지하는 것

- 입력 영역의 구성(출발 날짜 왼쪽, 편명 오른쪽, "조회하기" 버튼), 날짜 칸 아래에 안내 문구를 두지 않는 것.
- 결과가 나오면 입력 칸을 접고 "다시 조회"로 여는 동작.
- 공항 카드의 구성: 공항 코드와 이름, 현지 예정 시각, 날씨 아이콘·기온·체감·강수 확률, 라벨 없는 옷 목록과 지참 물품 배지.
- 날씨 코드와 강수 확률로 정하는 날씨 상태("비 올 가능성" 포함)와 옷 추천 규칙.
- 갈아입기 안내를 카드 아래에 두고, 날씨 차이는 "차이비교" 버튼 뒤에 숨기는 것.
- 편명 하나만 입력하면 1단계와 똑같이 두 공항만 나온다.
- 편명 데이터 출처, 키 관리, 출처 표기, 저장 기간은 [편명 데이터 출처](../../decisions/flight-data-source.md)를 따르고, UI 구성은 [UI 구성 원칙](../../decisions/ui-composition.md)을 따른다.

## 범위

- 입력은 첫 비행기의 출발 날짜(공항 현지) 하나와 편명 목록입니다. 편명 칸은 `1편`, `2편`처럼 번호가 붙고, "환승편 추가" 버튼으로 칸을 늘리며 `×`로 칸을 지웁니다. 최대 4편까지 받습니다. 좁은 화면에서는 날짜, 편명 순서로 쌓이고 편명 칸들도 세로로 쌓입니다.
- 환승편의 날짜는 입력받지 않습니다. 앞 편이 도착한 공항 현지 날짜부터 하루씩 최대 3일 뒤까지 조회해, 앞 편 도착 이후에 출발하는 첫 편을 그 환승편으로 정합니다. 비행 중 날짜가 바뀌거나 환승 대기가 다음 날로 넘어가도 실제 탑승 일시가 기준입니다.
- 환승이 있으면(공항 3곳 이상) 결과 맨 위에 "공항별 한눈에 비교" 영역을 두어, 모든 공항의 코드·시각·날씨 아이콘·기온·강수 확률·추천 겉옷·기본 옷·지참 물품을 스크롤 없이 한 줄에 나란히 견주게 합니다. 좁은 화면에서는 이 영역만 가로로 스크롤될 수 있습니다.
- 그 아래에 출발, 환승, 도착 순서의 공항 카드 목록이 이어지고, 카드 사이에 편명과 항공사를 보여 주는 연결 표시를 둡니다.
- 환승 공항 카드에는 도착 시각과 탑승 시각, 환승 대기 시간을 함께 보여 주고, 날씨와 추천 옷은 탑승 시각 기준입니다. 출발 공항은 출발 시각, 도착 공항은 도착 시각 기준입니다.
- 갈아입기 안내는 모든 공항의 겉옷을 이어서 안내합니다.
- "차이비교" 버튼 뒤에는 이웃한 공항끼리의 날씨 차이를 공항 쌍마다 한 카드씩 보여 줍니다.

## 범위 밖

- 귀국편(3단계), 같은 입력으로 편도 두 건을 따로 보는 것.
- 재접속 시 이전 입력 재조회와 오프라인 저장본 표시.
- 5편 이상, 앞 편 도착 공항과 다음 편 출발 공항이 다른 일정을 연결해 주는 것.

## 인수 기준

1. 편명 칸을 늘려 `KE17` 다음 환승편을 입력하면 출발, 환승, 도착 카드가 모두 순서대로 표시된다.
2. 각 카드의 시각은 해당 공항의 현지 시각이고, 환승 공항 카드는 도착 시각, 탑승 시각, 환승 대기 시간을 보여 준다. 날짜가 바뀌면 그 공항 현지 날짜로 표시된다.
3. 환승 공항의 날씨와 옷 추천은 탑승 시각의 예보다. 탑승이 다음 날이면 그날의 예보다.
4. 환승편의 날짜를 입력하지 않아도 앞 편 도착 이후에 출발하는 가장 이른 해당 편으로 정해진다. 3일 안에 앞 편 도착 이후에 출발하는 편이 없으면 연결 불가로 안내한다.
5. 편명 하나만 입력하면 1단계와 같은 결과(두 공항)가 나온다.
6. 편명 칸 중 비었거나 형식이 맞지 않는 칸이 있으면 조회 없이 안내하고, 안내에는 몇 번째 편인지 나온다. 날짜가 비었거나 지난 날짜일 때의 안내는 1단계와 같다.
7. 어느 편이든 찾을 수 없으면 몇 번째 편인지와 함께 "찾을 수 없다"는 안내가 나오고 빈 카드는 나오지 않는다.
8. 앞 편 도착 공항과 다음 편 출발 공항이 다르면 몇 번째 편인지와 두 공항 코드로 안내하고 결과를 보여 주지 않는다.
9. 예보 기간을 벗어난 공항은 그 카드에만 "아직 예보가 없습니다"가 나오고 다른 카드와 일정은 그대로다. 한 공항의 날씨 조회가 실패하면 그 카드에만 오류와 다시 시도가 나온다.
10. "차이비교" 버튼은 이웃한 두 공항의 날씨가 모두 있는 쌍이 하나라도 있을 때만 나오고, 누르면 그런 쌍마다 차이 카드가 펼쳐진다.
11. 결과가 나오면 입력 칸이 접히고 요약(날짜 · 편명들)과 "다시 조회"가 보인다. 다시 열면 입력했던 편명 칸들이 그대로 채워져 있다.
12. API 키는 브라우저로 전달되지 않고, 편명 데이터를 보여 주는 화면에 AeroDataBox 출처 표기가 있다.
13. 공항이 3곳 이상이면 결과 맨 위에 공항별 날씨와 추천 옷이 나란히 보이고, 예보가 없거나 실패한 공항은 그 칸만 "예보 없음" 또는 "날씨 오류"로 표시된다.
14. 좁은 화면(약 400px)에서도 입력 칸, 공항 카드, 연결 표시가 숨지 않고 가로로 넘치지 않는다.

## 확정한 제약과 근거

- `PRODUCT.md`: 출발 비행기를 입력할 때 모든 비행 편명을 받고, 환승편의 기준은 실제 환승편 탑승 일시이며 첫 비행기 출발 날짜 하나만 입력한다.
- 환승편 조회로 외부 호출이 늘어난다. 무료 플랜의 월 한도가 작아 검증 중 소진될 수 있다.
- 조회 조건은 주소에 남긴다(`date`, 반복되는 `flight`). 1단계 주소(`?date=…&flight=KE17`)는 그대로 유효하다.

## 가정(덮어쓸 수 있음)

- 최대 4편, 환승편 날짜 탐색 3일은 바꿀 수 있다.
- 환승 공항의 날씨 기준을 탑승 시각 하나로 하고, 도착 시각의 날씨는 보여 주지 않는다.
- 디자인은 1단계 구성을 따르며 별도 프로토타입을 만들지 않는다. 연결 표시와 환승 공항 카드의 세부 모양은 구현에서 정한다.
- 환승 대기 시간은 앞 편 도착 시각과 다음 편 출발 시각의 차이로 계산한다.
- 같은 편명이 한 날짜에 여러 건 응답되면 앞 편 도착 이후 출발하는 첫 건을 쓴다.
- 갈아입기 안내 문구의 규칙은 구현에서 정하되 두 공항일 때는 1단계 문구와 같다.

## 보류한 점

- 귀국편 입력과 날짜 규칙(3단계).
- 이전 입력 저장과 오프라인 표시.
- 서비스가 다루지 않을 범위(`PRODUCT.md`의 미정 항목).

## 남은 위험

- 환승편 날짜 탐색은 편명 한 개당 최대 4회까지 호출을 쓴다. 무료 한도가 빨리 줄 수 있다.
- 같은 편명이 며칠 간격으로 운항하는 경우(주 3회 등), 3일 안에 운항이 없으면 연결 불가로 안내되어 실제로는 가능한 일정을 놓칠 수 있다.
- 입력한 편명이 서로 이어지지 않는 일정(다른 공항 이동 등)은 지원하지 않는다.
